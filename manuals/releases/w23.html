W23 Release Manual

Features shipped in the W23 release across the BackOffice and Partner Portal. Each entry below links to the (release-agnostic) feature manual under Manuals by Domain.

The matching W23 work plan and per-feature acceptance gates are tracked in silkskyair-docs/plans/w23-work-plan.md.

Member Portal

  • Check-in is not part of Phase 1 — F2.1 MP1-W01 disables online check-in in the Member Portal. The check-in page, public magic-link entry, and check-in API all return 404; the booking detail page no longer renders the Check In Now / Complete Info banners. Every touched file carries the CHECKIN-DISABLED-2026-05 marker so Phase 2 can reactivate cleanly.
  • Sign In with Magic Link — F2.2 MP1-W02 makes Member Portal sign-in magic-link only. The /sign-in page renders an email field + Send Magic Link button only; password input, Forgot Password, and the "or sign in with password" toggle are hidden. Policy centralized in lib/auth/url-context.ts. Complex E2E walks the real n8n execution to extract the issued verify token and round-trip it through the verify endpoint.

Bookings

  • Cancellation Flow (Partner-initiated) — F1.15 R20 wires partner-initiated cancellations end-to-end: a BookingCancellationRequested event fans out to a banner on the partner detail page, a realtime in-app notification + bell badge for every back-office booking_manager, a manager email, and (new in W23) a customer acknowledgement email.
  • Booking Email Verification (Back-office) — F1.16 R21 adds per-booking lead-pax email verification: an amber/green badge on booking cards and the detail page, a 6-digit OTP drawer (auto-advance, paste-fill, "Send new code"), and a Manager API proxy to the verify edge function. Distinct from the member-account email badge; pairs with the api OTP-email migration (3b0a3e8) and the n8n booking-verification-email workflow (81e51d4).

Partners

  • Create a Partner (Back-office) — F1.1 R1 fixes the Manager partners-create drawer so it stays open in edit mode after Save, sets the URL ?partner=<id>, and rehydrates the same record on refresh.
  • Pay with Card (Partner Portal) — F1.13 R17 + R18 wires Omise card payment end-to-end on the Partner Portal's booking detail page: drawer-based payment that survives the Omise 3-D Secure / acs=false bounce by auto-reopening into the same Direct or Net Payment view and resuming polling against the existing intent.
  • Edit Passenger (Partner Portal) — F1.10 R12 + F2.3 MP1-W03 wires the inline passenger edit form: nationality via <NationalitySelector> (ISO-2 codes the FK accepts), weight as a positive numeric(5,2) kg value (FK to weight_ranges dropped; CHECK constraints enforce positive + ≤ 250). Member Portal also swapped to the numeric input in the same change.
  • Partner Home Dashboard — F1.5 R5 trims the portal home page to the two day-to-day widgets: Available Tours (left, replacing the Agreement widget) + Latest Bookings (right). The Commission Rate card and Performance Overview chart were removed (R5-DISABLED-2026-05), and the page no longer fetches performance metrics on load.
  • Commission & Payment Breakdown — F1.12 computes the full per-booking money split for both payment directions: VAT extracted from the inclusive total (× 7/107), commission on the service-excl-VAT amount, 3% withholding tax (Full Payment only), and VAT-on-commission (VAT-registered partners only), ending in net-to-partner / net-to-operator.
  • Net Payment Amount & PromptPay Parity — F1.14 R19 shows the TOTAL AMOUNT card and the PromptPay amount in both payment modes; previously both were Direct-only, leaving the Net Payment dialog without the figure.
  • Archive a Client — F1.17 R22 adds a one-way, idempotent client archive: a ⋮ menu → Archive → confirm dialog → POST /api/members/[id]/archive (org-ownership gated, api.archive_member RPC), plus a Show archived toggle and an Archived badge. Pairs with silkskyair-api e3813e5.
  • Partner Portal Label & Terminology Updates (W23) — F1.3 / F1.4 / F1.7 / F1.9 / F1.11 (+ R8, R10) — the string-only relabels from the Round 3 review, grouped: Members → Clients, Invite Member → Invite Team, Direct/Indirect Payment → Full / Net Payment, Confirm → Submit Booking, a humanised role formatter (organization_manager → Organization Manager), and more. Landed via the api i18n migration (202b619) + the BackOffice rename (042c7b2).

Meta CAPI

  • FB Attribution Capture, Dispatch & Recording — F3.1 + F3.2 + F3.3 captures Facebook attribution at the WebSite, forwards it through the booking submission, and dispatches a server-side Purchase event to Meta CAPI for every confirmed booking, recording every dispatch outcome as a MetaCapi* booking event.
