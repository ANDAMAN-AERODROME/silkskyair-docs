# W23 Release Manual

Features shipped in the W23 release across the BackOffice and Partner Portal. Each entry below links to the (release-agnostic) feature manual under **Manuals by Domain**.

The matching W23 work plan and per-feature acceptance gates are tracked in `silkskyair-docs/plans/w23-work-plan.md`.

## Member Portal

- [Check-in is not part of Phase 1](../domains/members/no-checkin.md) — **F2.1 MP1-W01** disables online check-in in the Member Portal. The check-in page, public magic-link entry, and check-in API all return 404; the booking detail page no longer renders the Check In Now / Complete Info banners. Every touched file carries the `CHECKIN-DISABLED-2026-05` marker so Phase 2 can reactivate cleanly.

## Bookings

- [Cancellation Flow (Partner-initiated)](../domains/bookings/cancellation-flow.md) — **F1.15 R20** wires partner-initiated cancellations end-to-end: a `BookingCancellationRequested` event fans out to a banner on the partner detail page, a realtime in-app notification + bell badge for every back-office `booking_manager`, a manager email, and (new in W23) a customer acknowledgement email.

## Partners

- [Create a Partner (Back-office)](../domains/partners/create.md) — **F1.1 R1** fixes the Manager partners-create drawer so it stays open in edit mode after Save, sets the URL `?partner=<id>`, and rehydrates the same record on refresh.
- [Pay with Card (Partner Portal)](../domains/partners/pay-with-card.md) — **F1.13 R17 + R18** wires Omise card payment end-to-end on the Partner Portal's booking detail page: drawer-based payment that survives the Omise 3-D Secure / `acs=false` bounce by auto-reopening into the same Direct or Net Payment view and resuming polling against the existing intent.
- [Edit Passenger (Partner Portal)](../domains/partners/edit-passenger.md) — **F1.10 R12 + F2.3 MP1-W03** wires the inline passenger edit form: nationality via `<NationalitySelector>` (ISO-2 codes the FK accepts), weight as a positive `numeric(5,2)` kg value (FK to `weight_ranges` dropped; CHECK constraints enforce positive + ≤ 250). Member Portal also swapped to the numeric input in the same change.

## Meta CAPI

- [FB Attribution Capture, Dispatch & Recording](../domains/meta-capi/attribution-and-dispatcher.md) — **F3.1 + F3.2 + F3.3** captures Facebook attribution at the WebSite, forwards it through the booking submission, and dispatches a server-side Purchase event to Meta CAPI for every confirmed booking, recording every dispatch outcome as a `MetaCapi*` booking event.
